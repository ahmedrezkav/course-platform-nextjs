# Internationalization

next-intl handles routing and copy. Locales are `en` (default) and `ar`. Prefixes are **always** shown (`/en`, `/ar`) so both languages stay visible while learning.

`src/proxy.ts` wraps next-intl’s `createMiddleware`. Next.js 16 loads that file instead of `middleware.ts`. `/` is redirected from `Accept-Language` (or the locale cookie after a switch).

## Copy vs data

- UI strings live in `src/content/en.json` and `src/content/ar.json`.
- Course titles, descriptions, and lesson bodies are bilingual fields on records in `src/data`.
- `brandName` is `"Vela"` in both locale files. Do not translate it.

## HTML and CSS

`[locale]/layout.tsx` is the root layout (`lang` and `dir` on `<html>`). Arabic sets `dir="rtl"`. New UI uses Tailwind logical properties (`ps` / `pe`, `ms` / `me`, `inset-s-*` / `inset-e-*`) instead of `left` / `right` or positioning `start-*` / `end-*`. Prefer canonical utilities (`z-100`, not `z-[100]`). The skip link is a hash `<a href="#main">` (not a locale `Link`); `<main>` is `tabIndex={-1}` so that jump can take focus. The mobile menu panel is anchored with `inset-s-0` so it opens from the inline start in both directions. The footer copyright is `dir="ltr"` so `©`, the year, and **Vela** stay in reading order under RTL. Header and footer nav landmarks use different labels (`shell.mainNav` vs `shell.footerNav`).
